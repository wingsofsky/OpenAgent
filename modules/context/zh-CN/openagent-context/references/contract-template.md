# 契约模板

一份空白的 `CLAUDE.md`（或 `AGENTS.md`），按[和 AI agent 一起干活](working-with-ai-agents.md)里的做法写成；决策日志从[决策日志模板](decision-log-template.md)起步。把分隔线以下的内容整段复制进你的项目，填好 `<…>` 的部分。不合用的删掉；只加那些你不想再说第二遍的规则。

两个习惯让它一直有用：

- **留下的每条规则都标出处**：`[owner]` 是你自己的话，`[agreed]` 是 agent 的建议、你同意了，`[incident]` 是返工得来的教训，`[D0xx]` 是决策日志条目。下面的规则在你采用之前都不带标记。
- **控制在 150 行以内。**进度、状态和历史放在最后一节列出的文件里，绝不放这里。

---

````markdown
# CLAUDE.md：<项目名>

<一两句话：这个项目是什么，给谁用。>
本文件只放每个会话都要遵守的规则。进度和历史在别处（见「东西在哪」）。

## 怎么和我协作

### 语言
- 一律用中文回复，包括中途进度和收尾汇报；代码、命令、路径、标识符保持原样。

### 问，还是做
- 我在提问、要分析或要对比时：回答，不改任何文件。
- 我说「只读」「先别执行」「等一下」时：停在当前状态。
- 大改动之前：用你自己的话复述我的目的和现状的差距，再写计划文件。我批了再开工。
- 拿不准我的意思时，按目的理解，不按字面。还是拿不准就问。

### 要我拍板时
- 列出「现在要你定的几件事」并编号。每件把推荐选项放第一个，写出代价（用户看到的会变什么、花多少钱、动到哪里）和备选。
- 推荐不等于拍板。记录时写清是我定的，还是我同意了你的推荐。
- 只由我定的事：<产品范围、命名、定价、许可证、对外措辞、换模型或执行者、提交、推送、发版、生产数据>。

### 范围
- 只做要求的事：不顺手重构，不加没人要的开关、护栏或兜底。
- 不新增、不升级依赖，除非先问过。
- 技术范围内的实现细节你来定；汇报里说一句，值得长期记住的写进决策日志。

## 证据和汇报
- 每个结论都标级别：verified（本会话跑过）、implemented（写了没跑）、hypothesis（推测）。拿不准就降级，绝不升级。
- 保真度从高到低：真实运行 > 集成测试 > 单测 > typecheck > 读代码。只有测试全绿不算完成。给用户看的改动要打开看一眼。
- 产出不好时先往上游找：给的信息够不够，再看提示词，最后才看模型。根因要有权威证据（日志、数据库、版本历史、真实请求），不能只靠读代码。
- 同一个办法失败两次，就换诊断思路，不试第三次。
- 每份汇报四块：改了什么、验证了什么（附证据）、没验证的、我要做什么。不是你造成的失败或改动，标明「不是本次引入的」。
- 先给结论。要讲结构或对比时，用图或表。
- 钱和 token 以厂商后台或账本为准，绝不估算。接新模型或新服务之前先报单价。

## 委派
- 小任务自己做。几个低风险的机械活合成一份任务书。难任务派出去，回来逐项核验。
- 任务书写给按字面执行的执行者：目标、工作目录、允许改的文件、不要做什么、什么算完成、回答格式。它没法追问。
- 发出前，任务书里每一条现状说明都对着当前 HEAD 核一遍；写明这次改动会打破哪些现有测试、怎么处理。
- 执行者说「做完了」不等于验收：先看 diff（是否只碰了允许的文件），自己跑测试，再记验收结论。
- 执行者不做 git 写操作；由主 agent 按精确路径提交。
- 一个工作树同一时间只跑一单。

## Git
- 按精确路径 add；绝不用 `git add -A` 或 `git add .`。
- 收尾前跑 `git status`，列出未提交的改动，标出哪些不是本会话做的。别的会话的改动不碰。
- 没有我的话，不提交、不推送、不打 tag、不发版。
- <提交信息格式，比如 Conventional Commits。>

## 项目不变量
<只放绝不能破的规则，每条写明由哪个测试或检查守着。>
- <不变量>：由 <测试或检查> 守。

## 常用命令
```bash

```

## 东西在哪
| 内容 | 位置 |
|---|---|
| 决策和理由 | `DECISIONS.md`，只追加；推翻就新开一条 |
| 跨会话的长期事实（偏好、环境的坑、外部资源） | agent 的记忆：`MEMORY.md`，每条一行，细节放单独的文件。反复出现的偏好，提议升进本文件 |
| 计划和进度 | `docs/plans/` |
| 报告、收尾、复盘 | `docs/reports/` |
| 调研和对比 | `docs/research/` |
| 操作说明 | `docs/guides/` |
| 架构 | `<架构文档>`；和代码冲突时以代码为准 |

每个会话开工先读最新的计划和最后几条决策，跑 `git status` 和 `git log --oneline -10`。不要假设上一个会话已经做完了。
````
